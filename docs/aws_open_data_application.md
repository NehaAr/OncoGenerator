**Name of dataset:** OncoGenerator-Endo: A Synthetic Clinical and Proteomic Benchmark for Endometrial Cancer

**Brief description of dataset:**
OncoGenerator-Endo is a fully synthetic, openly licensed benchmark for endometrial cancer research, generated by the open-source OncoGenerator framework. Each synthetic patient has clinical attributes (age, BMI, menopausal status, nulliparity, tumour type, grade, FIGO stage, histological subtype, treatment, survival outcome) and a linked log2 fold-change profile for 180 proteins. Values come from a probabilistic, fuzzy rule-based generator, with grade- and stage-dependent scaling and pathway-correlated noise. The release contains cohorts of 1,000, 10,000 and 100,000 patients, plus variants with different noise levels, class imbalance, batch effects and missing values. It also includes ground truth: per-protein generating parameters, true effect sizes for four clinical contrasts, true null proteins, noise-free expected values and the batch effects applied. This lets users measure a method's sensitivity and false-discovery rate exactly. No real patient data are used. The data are for method development, benchmarking and teaching, not biological conclusions.

**Size of dataset:** ~80 MB

**Growth rate of dataset in GB per year (if applicable):** Static. New versions are added as separate releases, under 1 GB per year.

**Dataset file format(s):** Parquet, CSV (gzip), JSON (data dictionary and manifest)

**Dataset license:** Creative Commons Attribution 4.0 (CC BY 4.0)

**How will this data be used?**
Benchmarking differential-expression, feature-selection and classification methods against known ground truth, for example with limma or scikit-learn. Testing how methods cope with noise, class imbalance, batch effects and missing values. Teaching bioinformatics and machine learning without access to patient data, and testing analysis pipelines. A typical workflow is to load the Parquet files in an Amazon Athena query or a SageMaker notebook and score a method against the ground_truth_contrasts table. The repository includes a script that does this (examples/02_de_benchmark.py).

**What's new or novel about this dataset or the way it is provided?**
Real endometrial cancer proteomics data is small and access-restricted, which makes fair method comparison hard. This offers a shareable, versioned alternative with machine-readable ground truth and ready-made scenario variants. The generator is deterministic (seeds, command-line tool, tests, SHA-256 manifest), so every file can be reproduced.

**How have you optimized this dataset to be used in the cloud?**
Typed columnar Parquet files, one per table, with no archives. Cohorts and scenarios are in separate folders, so users can query a 10,000-patient cohort without reading the 100,000-patient one, using Athena, DuckDB or Spark.
